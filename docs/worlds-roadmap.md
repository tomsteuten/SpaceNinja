# Worlds roadmap: from four bodies to the whole solar system

Written 24 September 2026 after the merge that put the guided adventure back at `/`.
This is the one planning document for the "more planets" goal. It exists because the
owner's target (every planet, some dwarf planets and moons, perhaps the Sun) is eight to
fifteen more worlds, and the code today pays a thirty-file cost per world. That is a cost
worth removing once rather than paying fifteen times.

Read `AGENTS.md` first. The testing rules there still hold for everything below.

## What the code looks like now

Saturn (commit `2dec85d`) is the honest measure of the per-world cost. Adding it touched
twelve files in the commit and its id is now hardwired in about thirty:

- **Geometry constants** were one named export each in `src/config.ts`, and **framing**
  was three named tiers chosen by two named gates in `src/main.ts`. (Since fixed: see step
  5a below; the names survive as re-exports.)
- **Reveal** is `revealAfterVisiting` on each destination, which is already data. Good.
- **Meshes** in `src/scene/Bodies.ts` were half generic: `createOrbitingBody` built the
  Moon and Mars from options, while Earth and Saturn were hand-built and the `bodies`
  record was written out body by body. (Since fixed: see step 5b below.)
- **Textures** in `src/scene/textures.ts` have a generated fallback per world
  (`makeSaturnTexture`), used only when the real map is missing from `public/assets`.
- **Copy and places** in `DESTINATIONS` are already data: six real places with real
  coordinates each, a spin lesson, a hunt line. Good.
- **Narration** is one JSON script keyed by cue id and one MP3 per cue in
  `src/audio/recordings/`, eleven cues per world, all-or-nothing per world. Generated by
  `npm run narration:generate` (Kokoro, local).
- **Stickers** are drawn by hand in `src/scene/shipDecals.ts` with a fixed hull position
  per id, and listed again in `src/state/progress.ts`.
- **The explorer** (`?explorer`) keeps its own `src/explorer/worlds.ts` list and its own
  thumbnails under `public/assets/explorer/`.
- **Tests** pin the four ids in `config.test.ts`, `Bodies.test.ts`,
  `Bodies.reveal.test.ts`, `selection.test.ts`, `shipDecals.test.ts`, `progress.test.ts`,
  `explorer/worlds.test.ts` and `e2e/visit.pw.ts`.

Nothing here is bad code. It is the right shape for four worlds and the wrong shape for
fifteen.

## The target shape: a world catalogue

One file, `src/worlds/catalogue.ts`, exports `WORLDS: WorldSpec[]` in reveal order.
Everything that today switches on an id reads the catalogue instead. A new world is then:
one catalogue entry, one surface map, six photographs, eleven narration lines, and one
sticker drawing. No code.

```ts
interface WorldSpec {
  id: string;                 // 'jupiter'; stable, written into saved progress
  label: string;              // 'Jupiter'; 'The Moon' keeps its article here
  emoji: string;              // tray chip and reveal announcement
  tint: string;               // the world's colour for the spin button and the theme

  // Geometry. Earth radius is 1. Radii are true to life below 2 Earth radii and
  // compressed above it, for the reason SATURN_RADIUS documents. Distances are always
  // compressed; orbits are around the scene centre, not the Sun.
  radius: number;
  orbit?: { radius: number; tilt: number; startAngle: number; speed: number };
  parent?: string;            // a moon orbits this world instead of the scene centre
  spin: number;               // radians per second, 0 for tidal lock
  axialTilt?: number;
  rings?: { inner: number; outer: number; file: string };   // ratios of radius
  nightMap?: string;          // 'earth-night.jpg'
  atmosphere?: boolean;
  surface: { file: string; fallback: 'rocky' | 'banded' | 'icy' | 'cratered'; roughness: number };

  // Progression.
  revealAfterVisiting?: string;
  sticker: { id: string; label: string; emoji: string };

  // Words. Exactly what DestinationConfig holds today.
  fact: string;
  spinLesson?: { label: string; name: string; fact: string };
  mission: { instruction: string; huntLine: string; successLine: string; discoveries: Discovery[] };
}
```

Derived, never written by hand:

- **Framing radius** for a set of revealed worlds is the largest
  `orbit.radius + viewRadius + 0.18` among them, where `viewRadius` is `radius * rings.outer`
  for a ringed world and `radius` otherwise. The three named tiers become this one function.
  The existing values fall out unchanged (2.95, 5.71, 10.23), so the tests that pin them
  keep passing.
- **Reveal order** is the catalogue order. `revealAfterVisiting` defaults to the previous
  entry; Earth and the Moon set `null` to be there from the start.
- **The tray**, the stickers list, `BODY_IDS`, the explorer's world list, and the
  narration completeness test all iterate the catalogue.
- **Generated fallback textures** become four families (rocky, banded, icy, cratered)
  parameterised by colour, instead of one function per world. They only matter when a
  real map is missing, so this is the last thing to generalise, not the first.

Bodies.ts keeps two builders: `createHomeWorld` (Earth: origin, night map, atmosphere)
and `createOrbitingBody`, which grows optional `axialTilt` and `rings`. Saturn becomes an
ordinary call of the second. The `bodies` record and `registrations` are built in one loop.

## The composition problem, and the answer to propose

"Tap the world you see" has a cost that Saturn already made visible: each outer world
forces the widest shot wider, and the inner worlds shrink. Fifteen worlds on one map
would turn Earth into a pixel on a phone. Three ways out, in order of preference:

1. **Shell spacing.** Distance is already fake, so outer worlds need not be far. Put new
   worlds on orbits that grow by about 0.8 per world (Jupiter 7.4, Uranus 8.2, Neptune
   9.0, and so on) with start angles spread round the circle and tilts alternating sign.
   Eight more worlds push the widest frame from 10.2 to about 16.6, so Earth in the widest
   shot ends up about 60 percent of its current widest-shot size. The tray is the reliable
   way to choose a world; the map is for looking and for the tap when it is easy. This is
   cheap, needs no new interaction, and the owner can judge it on the real tablet as each
   world lands.
2. **Neighbourhoods.** If shell spacing looks wrong at eight or nine worlds, split the map
   into two scenes, "near home" and "the giants", with a Fly Further button. This is a real
   feature (a second map centre, a transition, saved state for which map is open) and
   should not be built until shell spacing has been seen to fail.
3. **True order from the Sun.** Not proposed. Mars already orbits Earth in this scene, so
   the game does not teach solar order from the map and should not start pretending to.
   Solar order belongs in words: each arrival fact can say what is nearer and farther.

Moons (Titan, Europa, Io, Phobos) use `parent` and orbit their planet at two to three of
its radii; they are revealed by visiting the parent and framed with it. The Sun is not a
world to land on. If it becomes a destination, it is a "fly close and look" visit with
no surface hunt, which needs its own small design and is the last item on the list.

## Order of work

The owner's order stands: screens in the explorer's visual language, then flight polish,
then more planets. The catalogue refactor sits between flight polish and the first new
planet, because the first new planet is the moment it pays for itself.

1. **Moon arrival restyle** (the next screen; the prompt below). Weaker model.
2. **Earth, Moon, Earth day/night approvals**, one screen at a time, by the owner's eye.
3. **Discovery postcard and journal** in the theme. Weaker model, same pattern.
4. **Flight polish**: the parked ship half off the right edge at arrival; the tested
   free-flight steering as the candidate. Medium difficulty; a stronger model for the
   design of the steering, a weaker one for the parking fix.
5. **Catalogue refactor**, in three commits so each is green on its own:
   a. **Done, on `main`.** `src/worlds/catalogue.ts` holds the four existing worlds and
      derives the framing; `config.ts` re-exports the old constant names; `main.ts` frames
      whatever set of worlds is revealed. Tests pin the derived values to the old ones.
   b. **Done, on `main`.** `Bodies.ts` builds every orbiting world, Saturn included, from one
      builder (`createOrbitingBody`) driven by the catalogue: textures, bodies, registrations,
      the update loop and disposal are all loops. Earth stays hand-built (origin, paired maps,
      night lights, atmosphere). Adding a world to the scene is now one catalogue entry plus
      its id in `BODY_IDS`.
   c. **Done, on `main`.** The stickers (`progress.ts`), the ship badges and their mounts
      (`shipDecals.ts`, with a generic initial-on-a-disc badge and top-panel slots for
      worlds beyond the fourth), and the explorer's world list (`explorer/worlds.ts`, ringed
      worlds orbital) are derived from the catalogue. The generated fallback maps are two
      generators and a palette: `cratered` with a tint for any airless body, `banded` with
      two colours for any giant, plus the Mars-shaped `rocky`. The tray and the narration
      test already iterated `DESTINATIONS`. The words stayed in `DESTINATIONS` in config.ts
      rather than moving into the catalogue entry: it is 500 lines of copy that is already
      data, and `config.test.ts` pins its keys to the scene bodies. So a world is two data
      entries, geometry in the catalogue and words in `DESTINATIONS`, plus its id in
      `BODY_IDS`.
6. **Jupiter**, as the pilot new world. It is the one children ask for by name, its map
   is free (Solar System Scope, CC BY 4.0), and its Great Red Spot, bands and four big
   moons give six places without a surface. Radius compressed to about 1.7 (Saturn is 1.5
   and Jupiter is a little bigger). Weaker model, following the recipe below.
7. Then Mercury, Venus, Uranus, Neptune, Pluto, Ceres, Titan, Europa, one at a time,
   each shipped and looked at on the tablet before the next.

## Recipe: adding a world after the refactor

Every step is a file or a command. A world is done when all of them are.

1. **Map.** A 2048 by 1024 equirectangular JPG in `public/assets/<id>.jpg`. Solar System
   Scope maps are CC BY 4.0; credit them in `public/assets/README.txt` as Saturn's is.
2. **Catalogue entry** in `src/worlds/catalogue.ts`, after the world that reveals it:
   geometry, surface map and a fallback style with a palette, rings if any. Add its id to
   `BODY_IDS` in `src/scene/Bodies.ts`, in the same position.
2b. **Words** in `DESTINATIONS` in `src/config.ts`: emoji, fact, spin lesson,
   `revealAfterVisiting` (the previous world), and the mission with six discoveries at real
   coordinates, none above 55 degrees of latitude, the last one on the far side from the
   arrival so it takes a drag. `selection.test.ts` enforces both.
3. **Photographs.** Six NASA images in `public/assets/discoveries/<id>-<place>.jpg`,
   credited in that folder's README. Run `scripts/make-place-thumbnails.py` for the
   explorer's thumbnails.
4. **Narration.** Eleven cues in `src/audio/narration-script.json` (`arrival-`, `find-`,
   `hunt-`, `success-`, `spin-`, and six `discovery-` lines), then `npm run
   narration:generate`. The test fails if a world's set is incomplete, and the world
   stays silent until it is complete.
5. **Sticker.** Nothing required: a new world gets a generic badge (its initial on a disc)
   in the next free hull slot. A hand-drawn emblem in `src/scene/shipDecals.ts` can replace
   it later.
6. **Verify.** `npm run typecheck && npm test`, then `npx playwright test e2e/visit.pw.ts
   e2e/layout.pw.ts --project=tablet`. Send the owner full-resolution arrival images on
   phone, tablet and short landscape, and stop.
